# 门店收银身份核实简化

## 用户授权范围与验收

- 员工通过门店结算入口办理现金、微信、银行卡、余额及次卡业务，不要求顾客先核实身份或修改初始密码。保留员工认证、本店归属、金额重算和交易原子性。
- 顾客端仍需本人会话并强制修改初始密码；改密不自动标记身份已核实。顾客自行使用余额继续要求核实。当前次卡核销仅有员工入口，顾客凭证不可调用；不新增顾客自助核销入口。
- 不批量核实400多个档案，不更改客户密码、身份状态或门店价格。保留后台“确认顾客本人”供今后按需使用。

## 实施计划

1. 移除仅供员工使用的结算创建接口中微信异步支付的顾客核实拦截；核对数据库结算函数和次卡核销无同类限制。
2. 增加实际HTTP路由回归：未核实且弱密码顾客可经员工认证进入原子结算，匿名及顾客会话不能冒用员工入口；保留顾客改密后未核实仍不能自助扣余额的回归。
3. 执行隔离测试、构建、本地启动健康检查，记录未完成的浏览器/真实支付验收。仅本地修改，由用户手动提交推送。

不涉及数据库结构或函数修改，无新增迁移。

## 验证结果

- `npm run test:security` 17/17通过，`npm run test:transactions` 12/12通过。员工现金、银行卡、余额和非零微信结算在未核实/弱密码状态下可抵达事务入口（故意令RPC失败，未访问真实网关）；匿名和顾客凭证被拒。实际SQL测试覆盖未核实顾客的员工余额/次卡同事务完成，以及顾客商城未核实拒付。
- `npm run build`通过，既有主包体积警告；`git diff --check`通过。本地合成配置启动、health HTTP200后停止。
- 未执行浏览器/微信工具Network联调、真实微信收款或生产数据写入。保留这些验收边界，不标记真实支付验收完成。未暂存、提交或推送。
