# 外部平台审批前置检查（跨项目复用）

## 为什么要前置

功能代码完成不等于可以上线。本项目短信验证码接入中，资质与模板已审核通过，但签名在三家运营商仍显示“已报备待验证”，真实发送和送达尚未验收。外部审批可能使已完成的功能继续等待；本记录用于在其他项目立项时尽早发现同类依赖。

## 立项时执行

需求负责人在确定上线目标时，与开发、运营共同填写下表；每项指定负责人、提交日期、预期证据和未完成时的替代方案。外部流程与开发并行启动，排期按最慢的必需环节倒排。对短信类接入可先预留至少一至两周的计划缓冲，并根据平台实际反馈调整；这只是内部风险缓冲，不是服务商承诺的审核时限。

| 检查项 | 要确认的事 | 可留存的证据 |
| --- | --- | --- |
| 主体和资质 | 企业实名、经营主体、材料、管理员及授权人是否齐备 | 脱敏的资质状态和工单号 |
| 审批链 | 签名、模板、运营商报备等是否为不同节点；谁负责跟进退回材料 | 各节点状态截图和提交时间 |
| 资金和权限 | 计费方式、预算、充值/资源包、最小权限密钥和保管人 | 预算记录、权限核对结果；不存密钥 |
| 技术接入 | 数据库迁移、环境变量、域名/回调、正式部署与回滚条件 | 迁移及部署记录、脱敏配置清单 |
| 端到端验收 | 实际请求、平台返回、用户真实收到、业务登录和失败回退 | 脱敏发送记录、测试结果 |
| 运营交接 | 失败监测、账单预警、客服话术和负责人 | 验收记录与值班联系人 |

短信接入的状态必须分别记录为“材料已提交”“资质已批准”“签名已批准”“模板已批准”“运营商已报备待验证”“真实送达已验证”“生产业务流程已验收”。其中任何前一状态都不能替代后一个状态。不同平台流程可能不同，按其实际状态调整。

## 倒排和放行

1. 需求评审时列出外部依赖并确认主体、费用及负责人；审批材料可准备时立即提交。
2. 开发期间每次例会更新各节点状态、退回原因和预计影响；超过内部预留时间就更新上线计划，不以重复提交或大量发送代替核验。
3. 计划上线前，完成生产配置与新部署，使用授权的少量测试号码核对平台发送记录和实际送达，再测试真实业务、错误与回退。
4. 仅当必需节点都有证据，才标记功能“线上可用”；未通过则保留原有可用路径并明确告知运营。
