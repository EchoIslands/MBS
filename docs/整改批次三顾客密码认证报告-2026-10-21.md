## 范围与实现

- 新增 `migrations/025_add_customer_password_hash.sql`，只新增 nullable `customers.password_hash`。迁移未运行。
- 顾客手机号必须对应唯一的既有客户档案。首次输入后提示设置六位数字密码；后续手机号+密码验证。bcrypt 每次生成独立 salt，数据库只存哈希；响应和日志均不包含密码/哈希。重号返回门店处理提示，不自动创建档案。
- 小程序将 token 与 customerId 存在微信本地缓存。已缓存会话通过本人资料接口自动恢复；服务端过期或密码被重置时返回 401，客户端清除 token 并要求重新登录。H5 使用 HttpOnly Cookie。
- CEO/客服在客户详情可重置密码为手机号后六位；响应不返回重置密码。顾客端展示联系门店提示。
- 移除 15 分钟凭证签发 API、用途 token 和相应 UI。本人余额/资料/次卡及预约、评价、优惠券、商品订单列表要求本人 token，并按路径 customerId 校验归属。
- 顾客会话含当前密码哈希版本；密码重置后旧会话即时失效。登录尝试增加每实例 15 分钟内五次失败限制。

## 发布阻断与风险

- 首次设密只凭手机号，不能证明操作者是号码持有人。攻击者知道客户手机号即可先认领并设置密码，继而读取余额和个人数据。生产启用前必须加入可信 SMS OTP、已绑定微信身份或门店核实的一次性激活流程。
- 六位数字密码只有一百万种组合；当前限流在单个进程内存中，重启即丢失，也无法约束多实例/serverless。发布前应采用共享限流存储、按 IP 与账户联合控制、告警和审计。
- 员工重置为手机号后六位同样容易猜，且客服需要通过可靠渠道将它交给顾客。生产建议使用短时一次性重置流程并要求首次登录后改密；本批按项目主人指定行为实现，尚无自助改密界面。
- 小程序缓存 bearer token 可被设备本地环境读取；其有效期为两小时，退出或重置会使对应会话失效，但当前没有服务端逐设备会话撤销与审计。
- 数据库手机号没有唯一约束；本地按查询结果检测重复档案。发布前需在隔离库只读核对重复手机号和迁移结果，再决定清理或约束策略。
- `customer-packages/available/:customerId/:serviceId` 等其他顾客 ID 驱动的业务端点仍需独立授权审计；本批只收紧个人资料及上述列表读取，不宣称全项目顾客接口已全部闭合。
