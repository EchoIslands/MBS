# 本轮目标和验收范围

先完成已上线整改的验收闭环，再推进新的账务及运营改造。本轮补充只读数据库验收工具，检查 025–029 所需字段、数据库函数签名/权限、保护表 RLS，以及空密码和改密状态的汇总数量；工具不获取客户明细、不执行业务函数、不迁移、不初始化密码。全部查询置于 READ ONLY 事务，结束回滚；检查不通过非零退出。

修复生产启动异常向客户端泄露 message/stack 的问题：客户端只收到通用错误码与说明，服务器内部日志保留诊断。不放宽 JWT 或身份检查。

验收标准：隔离数据库验证正常结构、缺字段、危险权限及剩余空密码能分别识别，执行后数据不变；生产模式启动故障响应无内部路径或密钥；原有安全和交易回归、本地构建通过。脚本仅交付，由用户手动运行；本轮不连接生产数据库，不提交真实账号登录或资金请求，不自动提交/push。

## 第一步：只读数据库核验（由项目主人本地运行）

```powershell
Set-Location 'E:\01Programe\01MBS\MBS'
npx tsx scripts/verify-release.ts
```

复用现有 .env 的 SUPABASE_DB_URL 及 setup-db.ts 的本地连接配置，不用再执行 setup 或密码初始化。脚本在 READ ONLY 事务内查询，30 秒语句超时，始终回滚。不执行 SQL 函数，不输出连接串、手机号、客户 ID、密码或哈希。未连接生产数据库代跑。

输出说明：passed=true 表示本次静态检查通过；issues 为不通过原因；counts 只有数量；checkedFunctions 应为 10。成功退出码 0，检查不通过 2，配置/查询失败 1。

- empty_password：NULL/空字符串密码数。只有为 0，才能说“当前空密码已处理完”；无法证明历史每一个客户均已初始化，也不能证明顾客可登录。
- whitespace_password：纯空白字符的异常密码数。脚本只提示，不擅自覆盖。
- must_change_password：仍需首次改密的数量，大于 0 是业务待办，不自动判为故障。
- unverified：未由门店核实的数量，大于 0 是业务待办，不自动判为故障。
- total：客户总数。以上集合有重叠，不能相加。

结构检查验证客户字段存在、精确函数签名、service_role 可执行且 anon/authenticated 不可执行、三张保护表 RLS。并未比对函数源码、所有约束或历史数据一致性；不要把 passed 当成生产资金验收通过。空密码若有剩余，先查上次初始化终态和业务新增来源，不自动重跑批量重置。

## 第二步：三端操作验收

以下各项初始状态均为“待人工验收”。只使用独立测试 Supabase、测试部署和合成账号进行造数、扣费、并发及故障测试；生产仅核对部署/配置及正常业务实际结果，不伪造收款或试扣真实余额。不要把账号、密码、Token 或客户截图发进报告。

| 范围 | 页面与操作 | 预期结果 |
|---|---|---|
| 顾客登录 | H5 和小程序登录页，用已准备测试顾客的正确密码登录 | 进入本人会话；错误密码拒绝；密码不出现在响应或日志 |
| 老客户强制改密 | 受限测试顾客用初始密码登录，再尝试返回/深链打开个人中心 | 只允许改密或退出，服务端业务请求也拒绝；完成改密后才能进入业务页 |
| 会话恢复 | 小程序关闭再打开；H5 刷新；随后员工重置该测试顾客密码 | 有效会话恢复；重置后旧会话失效；不能继续查本人资料 |
| 身份核实 | 测试环境员工客户详情点击“确认顾客本人” | 记录核实状态；未核实线上余额支付拒绝；改密和核实两道条件分别满足后才放行 |
| 员工权限 | 测试发型师打开客户列表/财务，尝试新增删除客户；客服执行合法新增删除 | 发型师只见本店本人客户，无财务/新增删除权限；客服合法操作通过 |
| 店铺范围 | 测试环境本店店长修改设置，另一店员工尝试操作同店数据 | 本店授权修改通过，越店拒绝；不得测试生产他店数据 |
| 价格 | 测试结算选真实目录项目，尝试修改请求金额、数量、税额 | 服务端重算，篡改拒绝；合法手工改价遵守角色和最低价限制 |
| 次卡与余额 | 独立测试数据库同时发起两笔争用最后次数/余额的结算 | 成功金额/次数不超额；失败无残留流水/部分扣减；成功仅一次核销 |
| 失败与重复 | 隔离库模拟日志写入失败，重复提交结算/商城付款/余额退款 | 失败整笔回滚；重试不重复扣款、扣卡、退余额或库存 |
| 微信回调 | 测试商户/授权测试流程检查正确及错误金额、重复回调、数据库暂时失败 | 错误金额拒绝、重复不重复入账；失败保留支付映射并允许安全重试；核对网关实收 |

同一公网 IP 每天最多 10 次认证尝试，成功也占额度，连续 5 次失败锁 15 分钟。验收在独立测试项目开展，避免耗尽门店生产 IP 额度；不绕过或清空生产限流表。微信收款不能随数据库事务回滚，真实外部回调与人工补偿演练独立记录。
