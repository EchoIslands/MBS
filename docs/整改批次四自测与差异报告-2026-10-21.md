## 修改内容对照

| 文件/模块 | 之前 | 本轮行为 |

| `api/lib/settlementPricing.ts` | 前端总价直接落库 | 读取本店服务 JSON 目录、商品、客户会员、有效权益、次卡、团购券；重算金额并核对前端总价；拒绝非法税额、数量及项目 |
| 手工改价 | 只有前端显示控制 | 集中权限策略限制 CEO/收银员；服务端范围为原价×0.58×0.7 到原价；价格来源显式传递 |
| 收银前端 `Checkout.tsx` | 成功后额外调用次卡 consume，失败只打印日志 | 请求携带 `customerPackageId`；删除后置核销；显式携带设计师等级、改价、团购券 ID；恢复草稿时恢复相关价格状态 |
| 创建结算 | 先写 completed 再分散更新客户/权益 | `create_settlement_atomic` 同事务创建、预占资源，立即支付方式直接调用完成函数 |
| 完成结算 | 余额覆盖更新、权益、到店记录并行，错误未统一处理 | `finalize_settlement_atomic` 锁结算及客户，校验余额与资源，余额/流水/统计/权益/次卡/日志/到店记录/结算完成同事务提交；已完成重复请求不扣第二次 |
| 次卡独立核销 | 读次数+覆盖写入，日志失败不回滚 | 原子核销和日志写入；同预约同次卡重复核销返回已有结果；预占的最后次数不能被独立核销抢走 |
| 预约完成 | 独立再次自动扣次卡 | 移除重复扣次路径，次卡统一由结算核销；服务完成状态本身不再代表已经扣卡 |
| 纯结算草稿删除 | 分开删除 payments 和 settlements | 同事务释放次卡、权益和团购关联；已有网关支付映射的订单不允许直接删，避免迟到回调丢单 |
| 商城创建/支付 | 分开写订单、库存、优惠券、余额、流水 | 028 原子函数，数据库行锁扣减库存及余额，失败全部回滚；继续支付幂等 |
| 商城取消/余额退款 | 状态、回库存、返余额分步执行，可覆盖并发余额 | 同事务处理；重复取消不多退库存，重复批准退款不多返余额；退款审批校验财务权限与同店 |
| 顾客到店付款确认 | 顾客调用接口可自行标记 paid | 顾客接口明确拒绝自认已付，由员工收款流程确认 |
| 微信订单初始化 | 先调用网关再保存支付映射 | 先保存固定支付 ID 映射再调用网关；调用失败保留映射供回调/对账 |
| 微信回调/收款确认 | 先改完成状态，缺少完整金额核对 | 核对签名后的商户、应用、币种、金额及本地订单映射；先调用数据库事务完成，再响应成功；真实人工确认先向网关查询金额/已付状态 |
| 网关重试/支付宝 | 生成新支付订单、支付宝未形成真实付款闭环 | 拒绝为同结算重复生成可付款订单；支付宝未接入时明确拒绝，不显示伪成功 |

金额规则沿用当前共享会员计划和固定权益抵扣规则；本轮不改变会员价格配置管理的整体设计。次卡每结算只能抵扣一个匹配服务一次；不允许同项目混用次卡、团购和手工改价。没有本店目录来源的任意补录金额会被拒绝，补单应选择真实项目后按权限改价。

## 终极联调必须覆盖的边界

1. 真实独立 Supabase 测试项目：按真实历史结构执行迁移，验证 service_role RPC、schema cache、RLS、并发两个收银员+顾客商城+退款。不得在生产试扣余额。
2. 微信已收款属于外部系统事实，数据库不能回滚微信收款。数据库失败时保留 pending 和预占资源，回调返回失败让平台重试；仍需真实回调、对账和人工补偿演练。本轮没有新增自动退款/自动对账后台。
3. 已产生支付映射的未完成单不能直接删除/重复开网关单；当前没有自动到期释放与关单界面。支付初始化失败或顾客放弃支付时，门店需对账后处理，不能直接清掉预占。
4. 既有股东权益/推荐奖励仍为非核心异步发放；未改造成事务 outbox，失败需核对，重复回调竞争下非核心奖励的完整幂等不是本轮验收结论。预约完成的历史统计/奖励与结算统计之间的重复口径亦需后续统一。
5. 本轮覆盖结算扣款、次卡核销和关联商城交易，不代表所有后台手动余额调整、入会充值、团购管理、预约状态和其他历史接口都已完成全项目安全审计。尤其手工余额管理仍需单独的账务调整事务及审计设计。
6. IP 日限额为用户指定的严格策略：同门店 Wi-Fi 共享公网 IP 会共享 10 次/日；成功登录不清额度。部署联调需要确认真实客户端 IP。Vercel 路径仅在 VERCEL=1 时读取平台覆盖的专有转发头；其他反向代理路径未自动信任任意 X-Forwarded-For。
7. 已核实只证明门店人工确认过，不是短信或实名验证。密码重置改变密码版本使旧 token 失效；号码归属异常依然由门店处理。旧未设密档案默认为未核实。
8. 新代码开始产生资源预占后，不得直接回退到忽略预占字段的旧核销代码；应先停止交易并对账处理未完单。迁移均为追加结构，不提供自动删表回退脚本。

当前结论：本地代码与合成回归完成，保持未发布；隔离 Supabase、多连接与三端真实支付联调未完成。
