# 小程序登录密码显隐与会话失效恢复

日期：2026-10-27

## 需求和范围

登录页密码输入框增加小眼睛，点击切换明文/密文；首次设密的确认输入框同样支持，默认隐藏，离开页面恢复隐藏。保留六位数字校验、密码输入和现有登录接口。

截图显示本人资料接口返回401，仅据此可以认定凭证被拒绝，不能区分过期、无效签名等原因。请求封装此前仅清缓存，没有统一退出页面；首页串行等待店铺后才读本人资料，且店铺加载异常分支引用未定义的startTime，会二次抛错并持续显示加载。

修复小程序请求失效处理、首页加载顺序和异常反馈。服务端认证规则、有效期、数据库、定价均不变，不操作生产客户数据。

## 验收

- 两个密码框默认隐藏，独立切换后输入值不丢失；首次设密和离开页面后恢复隐藏。
- 当前会话的401清除本人缓存并回到登录页，页面说明需要重新登录；错误密码提示不触发反复跳转。
- 老请求晚到的401不能删除新会话；403强制改密守卫继续生效，网络错误与503不注销会话。
- 首页本人资料校验不等待店铺请求；加载失败结束loading，提供错误和重试。
- 本地行为回归、构建、API健康检查；微信开发者工具/真机密码显隐与Network需明确记录实际验证范围。

## 登录框视觉修订（主人反馈后先行记录）

- 替换临时 CSS 椭圆眼睛为与现有 Lucide 线性图标风格一致的显示/隐藏图标，使用本地透明图片供原生 image 渲染，避免内联 SVG 在小程序中不显示。
- 去掉手机号框独有且未正常显示的前置图标占位；三个输入框统一左内边距、字体和高度，首字符严格对齐。输入框通过 flex 居中并显式允许收缩，尾部按钮独立绝对定位并保留点击区域，避免原生 input 默认宽度和按钮布局挤压图标。
- 不更改登录校验、密码值、接口或经营规则。检查三个输入框对齐、眼睛位置/显隐状态及既有登录恢复回归；注明真实微信与替代渲染验证的边界。

## 本地结果

- 显隐图标改为本地 Lucide 细线透明 PNG（两个图片合计约 4.7 KB），同时保留 SVG 源文件及许可证。按钮指定 mini 尺寸并提高组件内样式优先级，避免微信原生普通按钮默认宽度覆盖图标按钮宽度。
- 微信开发者工具已重新编译，登录页原生渲染中手机号与密码占位文字左起点一致、垂直居中，隐藏态图标固定在框内右侧；无需外部图片请求。不代输入账号密码、不执行登录，首次设密实际页面和真机点按仍待主人核验。
- 10/10 相关回归通过，覆盖独立显隐、不丢输入、离开隐藏、401 并发/旧响应、新旧会话隔离、网络失败保留会话和首页加载失败。生产构建含类型检查通过；该构建不替代小程序编译或真机验收。合成配置本地 API 健康检查 200，diff 空白检查通过。
- 没有数据库迁移、生产写入、登录或支付操作，不代暂存、提交、推送及上传；小程序发布仍需微信开发者工具单独上传。
