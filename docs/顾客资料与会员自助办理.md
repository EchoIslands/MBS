# 顾客资料与会员自助办理

> 2026-11-13：项目主人反馈生产库 050 已成功执行，勿重复运行；维护者尚未独立只读核验。代码仍在本地，微信商户配置、实际小额支付和退款流程仍须验收，**不代表生产支付已经开通**。

## 顾客可做什么

- 小程序「我的」及 H5 个人中心顶部可编辑本人头像、称呼、性别、生日。手机号不能自行改动；账户余额、积分和会员等级也不能由资料接口改动。头像限 2 MB PNG/JPEG/WebP，存放于本人店铺及顾客目录。
- 「办理 / 续费会员」进入同一规则的购买页：VIP 29/59/79/99 元，储值 500/1000/2000/5000 元。顾客看到完整金额和权益后确认微信付款；未经微信验签与查单成功，不激活会员。
- 有效期内仅支持**同档续费**，按该档完整价格收取，不采用旧店铺端“补差”展示规则。VIP 自当前到期日顺延 365 天；储值资格顺延 730 天，储值本金全额计入余额。过期后可选新档。有效期内跨档调整须由门店确认价格及既有权益。
- 支付中的原单可核对或继续支付；收款后资料被店员并发调整时标为「待核对」，保留微信交易号，不覆盖人工改动，也不允许顾客重复下单。门店应核对订单、到账及会员状态后处理。

## 数据与安全

- 050 建立 membership_payment_orders，限制同一顾客只有一笔待付/待核对订单，交易号唯一；finalize_paid_membership_order 在单个数据库事务中锁定订单与顾客，核对金额、等级快照，登记 payments 微信收款台账，并调用 035 的 apply_membership_atomic 写入会员、权益、储值流水。重复通知幂等；待核对的已收款订单也保留台账。
- 下单金额服务端根据共享方案重新计算，数据库再次核对；顾客身份来自签名会话，不信任客户端上传的顾客或店铺 ID。小程序付款先以 wx.login 换 openid，再由微信 JSAPI/小程序下单取得 prepay_id；H5 使用微信 H5 支付，须在外部手机浏览器打开。
- 回调必须经微信支付签名及 AES-GCM 解密验证、商户号/AppID/订单号/金额核对后才提交入账；用户点击“核对支付结果”也由后端调用微信商户查单。微信支付页返回或 wx.requestPayment 的前端 success 回调本身不是入账依据。
- 资料编辑及头像上传均要求本人会话。H5 使用现有同站点 cookie，小程序使用本人 Bearer token。
