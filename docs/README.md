## 维护规则

- **事实位置**：现行现场写 `current-state.md`；经过验证的部署操作写 `DEPLOYMENT.md` 顶部；稳定规则写宪章或专用运行文档；背景和取舍写状态日志及专项文档。相同状态只留一个现行权威入口，其余用链接。
- **责任与审核**：开发者在每次重大改动、迁移、部署、故障或交接时更新受影响文档并标明验证证据；项目负责人确认经营规则和生产发布状态。未取得线上证据标为“待核实”，不得写成已上线。
- **安全边界**：不保存密钥、口令、客户手机号和证件原件；截图、发送记录、账单须脱敏。引用代码文件、迁移号、提交或平台工单时注明日期；外部规则的时效需重新核对。
- **复核节奏**：活跃开发期每周快速复核现状和失效链接，稳定期每月复核；重大事件即时更新。记录复核日期、范围及处理，不因例行复核改写历史。这里是工作约定，不代表已设置自动提醒。
- **归档与恢复**：只有确认文档被取代、无运行依赖且链接已处理时才按日期归档，保留可追溯来源；不能确定时保留原位。Git 历史和原文件共同承担恢复，不擅自重置未提交内容。
- **验收**：陌生接手者应能从此页找到目标、当前阶段、约束、数据来源、上线限制和下一步的验证方法；若现行记录与代码/平台矛盾，先标明冲突并核实，不按旧计划直接执行。
