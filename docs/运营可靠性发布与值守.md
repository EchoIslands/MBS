# 运营可靠性发布与值守

核对日期：2026-11-14。实现、隔离测试、生产部署、平台授权、真实设备验证分开记录；本文件不声称生产已完成外部配置。

## 会员办理约定

VIP同档续费收完整年费，从当前有效期末顺延365天；已过期则从办理时间起算。有效期内升档只收差价，保持原有效期，仅补新增种类权益；降档不自动退款、不重新赠送权益。取消VIP只取消折扣资格、保留历史记录、储值余额及已有次卡；储值资格与VIP分别处理。

店内办理先展示操作类型、应收金额和到期日，再确认已收款。操作编号在失败重试时保持不变，服务器和051原子审计共同防重放；不同顾客/操作者/请求不能复用编号。线上待支付或已收款待核对时阻止店内直接改档和旧撤销入口，避免改坏原付款约定。取消VIP同时撤销活跃的VIP入会记录。旧入会记录撤销必须匹配当前档位，不能拿历史低档记录撤销当前高档。

线上新单通过053记录开通/续费/升档意图；历史待支付单保留原金额和合同。老客户端仍能按原完整年费开通、同档续费；差价升档须由新版页面明确确认报价。可信微信收款凭据只入账一次，不以客户端“支付成功”直接开通。

## 已收款待核对

入口：收银与售后 → 收款异常与运营核对，仅负责人和店长可进入。

- 未付/未知：核对原单，不生成第二张订单，也不再次扣款。
- 已收款、会员快照冲突：负责人读取当前快照、填写原因并与顾客确认。完整年费单可按原档补开并顺延一年；差价升档不得覆盖改变后的约定。054在同一事务校验原收款、当前快照及权限，保存处理前后审计，重复提交不会重复加权益。
- 退款：当前按钮只登记已经实际完成的原渠道全额退款凭据，不向微信自动发起退款。必须先在商户平台完成退款，核对金额、退款号和北京时间，再登记。原收款历史保留，处理单标为已退款，不再被重复回调开通。退款审计须与财务结账一起核对，不能把原始收款流水直接当作退款后的净收入。
- 服务收款/服务退款/商品退款分别指向原业务页面核对；“待支付”不等于“丢单”。

## 排队离页通知

052在叫号/准备返回事件的同一数据库事务写入待发任务。发送与现场动作分离，避免慢微信/短信接口阻塞前台叫号。独立worker约每5秒检查一轮，实际到达还受平台及网络影响，不承诺锁屏必达。

顾客在排队页主动订阅，一次授权最多消费一次发送额度；openid由服务端交换微信登录凭证取得，客户端不能提交别人的openid。优先微信订阅消息，未确认受理则尝试已审核的排队通知短信；两者未确认转电话。平台受理不等于到达，也不等于顾客确认。页面继续每5秒同步，离页不靠页面定时器。

数据库租约超时的未知发送状态转电话，不盲目重发；过期、已确认、已取消、已开始服务、已结束、过号或被正式叫号替代的提醒不再发送。前台“需关注”显示电话兜底原因，使用原联系记录登记结果。

服务端配置：

| 配置 | 含义 |
| --- | --- |
| WECHAT_MINI_APP_ID / WECHAT_MINI_APP_SECRET | 小程序服务端身份凭证 |
| WECHAT_QUEUE_TEMPLATE_ID | 微信审核通过的订阅消息模板ID |
| WECHAT_QUEUE_NAME_FIELD / WECHAT_QUEUE_NOTICE_FIELD | 模板中两个不同的thing字段名称，须与审核内容匹配 |
| WECHAT_NOTIFICATION_STATE | 消息跳转版本，默认formal |
| SMS_QUEUE_TEMPLATE_CODE | 阿里云单独审核通过的排队通知模板，不可套验证码模板 |
| SMS_SIGN_NAME / SMS_ACCESS_KEY_ID / SMS_ACCESS_KEY_SECRET | 短信签名和仅短信发送权限的服务端凭证 |
| QUEUE_DISPATCH_SECRET | 独立至少32位随机密钥，绝不能放入客户端构建变量 |
| QUEUE_DISPATCH_URL | worker端完整HTTPS地址，例如正式域名/api/queue-notifications/dispatch |

短信模板参数为 `status`，内容为“即将轮到，请准备返回门店”或“已叫号，请在10分钟内到服务位”，须与实际审核模板相符。未配置、平台拒绝或发送未确认会进入电话兜底，不冒充已送达。

在可信常驻主机使用独立环境文件配置worker，先执行 `npx tsx scripts/queue-notification-worker.ts --once` 核对，再由进程管理器运行 `npx tsx scripts/queue-notification-worker.ts`。重启后仍须自动拉起；监控停止和电话待办。未实际配置常驻worker时，不能宣布离页通知已上线。不要用不支持该频率的套餐定时器替代。

## 时长、直接操作与统计

发型师台顶部直接展示当前服务、下一位；更新剩余10分钟、结束计时、叫号和开始服务无需层层进入。暂停或快照陈旧时禁用接客动作。服务结束计时与结算分开，不自动收费。

估计按同一发型师+同服务分组，读取最近90天、最多1000条有效记录。排除取消、未来、无效日期及少于5分钟/超过480分钟样本。至少8例才采用历史P50至P85，否则用服务参考时长的0.75–1.5倍；人工剩余时间优先。等待范围不是准点承诺，过时进度继续标注不确定，不自动结束服务。

运营核对台近30天指标包括到店至开始服务的等待中位数/P90、样本数、过号顾客数、到店后取消、店内续费操作数和通知转电话数。等待含暂离；取消不推断原因；续费次数不是转化率，也不包含尚未合并统计的线上续费。财务列表每类最多500条、指标每类最多1000条，达到上限明确提示不是全量；任一查询失败不展示伪完整结果。

小程序内存只记录粗粒度请求组、耗时、状态和大小，最多200项，不记录令牌、手机号、顾客ID、参数或响应正文；不持久化为用户画像。商品/头像延迟加载，队列与资金结果不做跨请求结果缓存。本机1000历史样本、100项估计的合成基准：重复分组约148.86ms，快照预分组约1.04ms，结果一致；仅此环境的计算证据，不代表真机或网络提速比例。复测命令：`npx tsx scripts/benchmark-queue-estimates.ts`。

## 加密备份与隔离恢复

工具 `scripts/backup-drill.ts` 使用独立64位十六进制 `BACKUP_ENCRYPTION_KEY`，AES-256-GCM验证加密归档，密钥另行托管。备份与各public表的行数/内容校验处于同一个只读快照；自定义归档保留表、函数、RLS和ACL。文件必须保存在仓库外的受限目录，不能提交Git或上传公开位置。

需要兼容数据库主版本的 `pg_dump` / `pg_restore`，可通过 `PG_DUMP_PATH` / `PG_RESTORE_PATH` 指定。TLS必须验证证书；缺可信根证书应安装正确证书或配置PGSSLROOTCERT，不关闭验证。此工具仅备份public schema，不涵盖角色定义、对象存储图片、托管认证系统及其它schema，完整灾备需分别保存这些资源。

备份：`npx tsx scripts/backup-drill.ts backup E:/MBS-backups/backup-20261114.mbsenc`。默认拒绝覆盖已有文件。

恢复：在全新的隔离库先创建必须的角色（anon/authenticated/service_role）及所需扩展，通过单独环境文件设置 `BACKUP_RESTORE_DB_URL`，执行 `npx tsx scripts/backup-drill.ts restore E:/MBS-backups/backup-20261114.mbsenc`。工具拒绝源数据库、当前生产库及存在业务表/视图/序列/函数的目标；只过滤已存在的public schema创建项，保留权限恢复。恢复在单事务内执行，完成后逐表核对行数和内容；还须用只读发布检查、余额/订单/队列业务查询复核。禁止把下载成功或加密测试当作生产可恢复证明。

目前缺本机PostgreSQL CLI及已核实的空隔离目标，生产TLS问题尚未解决：只完成归档认证、防误恢复保护、目录筛选与隔离SQL测试，未完成生产备份恢复演练。

## 发布顺序和保留项

1. 本地及CI全套检查通过后审阅准备分支，核对备份和回滚条件；保持现行已审核小程序不被自动覆盖。
2. 用户于2026-11-14确认线上051–055全部成功，046–050也已确认，不要求重跑。下一步合并main并部署配套后端/H5，检查实际部署提交和运行结果。本机直接数据库只读核验仍受TLS证书链错误阻断；不能把用户执行反馈标记成助手独立核验。
3. 配置审核通过的微信/短信模板和常驻worker，再做微信成功、微信拒绝转短信、双方失败转电话、超时转电话、过期不发及重复处理验证。
4. 下一小程序包包含新UI/订阅授权/邀请领取等客户端修正，体验后按平台流程发布；新生成的小程序邀请图默认正式版。详见《邀请新人扫码与登录说明》。
5. 真机验证与真实支付/退款/通知不以本地合成测试替代；生产恢复演练仍为发布值守待办。
