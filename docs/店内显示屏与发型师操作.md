# 店内显示屏与发型师操作

店铺登录后，在实时排队工作台点击“打开店内显示屏”，也可访问 /shop/queue-display。使用店长、客服、CEO或显示屏专用账号可显示全店；普通发型师账号仍仅能查看本人范围。点击全屏进入展示模式。显示屏不展示顾客姓名、电话和交易金额，展示发型师头像、姓名、服务状态、服务项目、叫号和现场等候人数。员工有已保存头像时优先显示真实头像，没有头像或图片加载失败时显示本地生成的姓名首字头像，不依赖外部头像服务。每2秒请求同步，异常或超过20秒未同步时提示核实并隐藏旧业务状态。不是锁屏通知。

发型师可用自己的员工账号在手机网页操作本人顾客，也可在显示屏账号的公共画面点击本人头像后输入自己的登录密码，直接操作本人状态。开始/结束必须对应实际服务，暂停不结束当前服务。店长、客服和 CEO 可在工作台代操作。显示屏账号默认只读，任何同屏写入都必须经过发型师本人身份校验。

本次新增061迁移，需在目标Supabase执行。H5需要部署，小程序首页优化需要重新上传：首页门店和评价请求并行，门店返回立即显示，不再等待评价；不缓存会员价格或排队状态。尚未以店铺手机实测量化提速；首个门店请求、图片下载及弱网仍需现场验证。

## 2026-11-20 显示屏专用账号与发型师同屏操作

- 新增 `queue_display` 店内显示屏专用员工角色。该账号只进入 `/shop/queue-display`，默认只读，可查看全店发型师头像、服务状态和现场等候人数，不能访问管理导航、预约管理或直接修改排队数据。CEO 可在店铺与员工管理中创建该账号，使用独立手机号和密码。
- 显示屏进入操作模式后，发型师点击本人头像卡片并输入自己的员工登录密码。服务端会再次校验发型师、门店、启用状态和本人归属，再以该发型师身份调用既有排队 RPC。显示屏不会保存密码到本地，也不能操作其他发型师。客服和 CEO 继续使用员工操作台代操作，发型师本人仍只能操作自己的队列。
- 快捷操作覆盖暂停20分钟、恢复接客、叫下一位、开始服务、更新剩余10分钟和结束服务。所有写入仍走同一套带版本号的数据库事务，发生并发变化会拒绝旧操作并要求刷新，客服、CEO、显示屏、顾客端按服务器结果同步。
- 显示屏轮询间隔调整为2秒，页面恢复前台、网络恢复和手动刷新会立即重新读取，20秒未同步仍显示旧状态不可作为依据的警告。当前系统的“绝对同步”指数据库单一事实源、原子写入和版本冲突保护，网络本身仍可能存在短暂传输延迟。
- 四种操作入口没有业务优先级：发型师手机或网页本人操作、显示屏本人解锁操作、客服代操作、CEO代操作均可执行。显示屏账号不会关闭发型师手机端权限，发型师也不需要先退出手机端才能在显示屏操作。所有入口都提交到同一条排队事务，必须携带最新版本；并发时先提交成功的一方生效，后到的旧版本会被拒绝并提示刷新。
- 新增 `migrations/061_queue_display_account.sql`，仅建立显示屏账号查询索引，不要求修改既有员工角色数据。迁移需在目标 Supabase 项目执行后，创建显示屏账号再登录使用。已通过类型检查、lint、构建和全套271项回归测试，尚未进行店铺实机大屏触摸验收。
