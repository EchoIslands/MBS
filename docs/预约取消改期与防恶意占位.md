# 预约取消、改期与防恶意占位

2026-11-14。本文是本轮新增规则的说明；代码位于发布准备分支，未据此宣称正式环境已更新。

## 顾客怎样操作

- 小程序「我的 → 我的预约」每条未开始预约直接显示「修改时间」「取消预约」；排队状态页也提供入口。H5 同步提供。
- 未签到、未开始服务时可以改到未来14天内、门店营业时间内且有容量的到店时间；日期按北京时间计算，包含今天和第14天。创建页面同步显示这个范围。
- 新时段验证与旧预约更新在同一事务内完成。时段冲突、限流或网络故障不应解释为改期成功；失败时刷新核对原预约，不能先取消再尝试新时段。
- 已签到排队可以取消；修改时间、更换服务或发型师请前台协助。已开始服务不能自行取消或改期；有收银占用的预约仍受原收银事务保护。
- 取消是幂等操作，确认后立即释放预约容量。门店和顾客排队页面下一次成功同步时显示取消状态；离线页面不承诺实时送达。
- 预约是到店时间段，不保证准时开始剪发。现场排队、暂离、过号规则仍按《预约系统详细逻辑介绍》执行。

## 防占位默认规则

| 条目 | 实际规则 |
|---|---|
| 有效预约 | 每位顾客最多2个尚未到期或已在现场队列的未完成预约 |
| 同一天 | 同一门店每天最多1个未取消预约；增加服务请联系前台 |
| 身份归并 | 同一门店相同手机号的顾客记录合并计算，不能换顾客记录绕过 |
| 新增频率 | 同一手机号10分钟内最多创建5单，取消也不清除计数 |
| 改期频率 | 单顾客滚动24小时最多成功改期5次 |
| 门店容量 | 每30分钟到店时段最多为本店有效发型师/店长人数，最低1位；指定发型师仍受原服务时长冲突保护 |
| 重复点击/超时重试 | 两端发送请求键；相同键相同预约返回原单，不再新增；相同键不同内容拒绝 |

门店容量目前按有效员工目录计算，未自动将请假/轮班表解释为可预约容量；排队暂停与未来排班并非一回事。请维护有效员工状态。规则由后端和数据库事务执行，不能仅靠按钮限制。

旧客户端无请求键仍可调用新后端，但数量与频率限制照常生效。既有历史记录、管理员导入与财务回归数据不回填、不追罚；新HTTP预约由服务端强制设置 `booking_policy_enforced=true`，顾客改历史预约时间也会启用新规则。该标志不接受客户端输入，匿名/顾客数据库角色无业务表写入权限。

## 正常取消与爽约分开

- 提前2小时以上取消/改期：正常变更。
- 不足2小时：记录为临时变更，不自动计爽约；门店发起的待处理延误不记顾客临时变更。
- 到店开始时间超过60分钟、尚未签到/进入现场队列、没有开始服务的已确认预约，才能由前台联系核实后确认未到店。待门店确认的预约不能直接记爽约。
- 到店后暂离或叫号过号不计此类爽约。门店延误、协商改期、漏签到或系统故障必须先核实，不能自动处罚。

## 门店处理与恢复

预约管理页的「到店核实 / 爽约管理」可展开近7天待核实预约，直接拨号并填写联系时间、结果和原因，至少5字；每30秒刷新，也可手动刷新。列表最多100条，达到上限会明确提示。

客服、店长、CEO可以确认；只有店长/CEO可以「纠正误判」。确认会取消占位并写入独立审计记录，同一预约重复确认不重复计次。

| 近90天有效确认次数 | 影响 |
|---|---|
| 1次 | 不限制自助预约 |
| 2次 | 自最后一次确认起14天内只约当天，最多1个有效预约 |
| 3次及以上 | 自最后一次确认起暂停自助预约30天，可联系门店安排 |

纠正记录保留原确认和更正原因，立即重新计算限制；不会自动复活已取消预约，以免重新挤占他人时段。限制不改顾客会员等级、余额、订单或售后权限；没有自动扣款、预约金或自动退款。

本轮未新增短信/微信「预约前提醒」模板和发送任务；前台核实列表是已实现的未到店处理入口。之前建设的微信排队通知→短信→电话待办仍依赖对应模板和常驻任务，不能把代码存在说成真实渠道已运行。
