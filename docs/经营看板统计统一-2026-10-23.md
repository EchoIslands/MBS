# 经营看板统计统一计划及验收

## 已确认问题

- 首页按本机日期及结算创建时间统计今日金额；预约今天使用UTC日期；请求失败被吞掉，初始零值被误认为真实结果。
- 老板视图总金额、店铺明细、设计师排名按创建时间计算。切换周期只改总卡片、明细仍本月且未明确说明；增长率随机生成。预约顾客数无结束边界，包含未来日期和取消预约。
- 发型师金额按创建时间；“本月接单”和类型分布实际包含全部历史；旧表明细丢失、查询默认1000行截断、失败显示空业绩。预约日期使用UTC，员工ID只比较旧字段。

## 执行计划与标准

1. 提取财务已有的分页数据读取，财务、老板、发型师共用可信支付关联和旧项目兼容，错误拒绝返回部分汇总。微信成功时间、其他渠道登记时间、缺证据不计入规则保持一致，不泄漏全店原始交易给发型师。
2. 首页今日金额复用同一统计规则，按北京时间加载今天预约，失败显示未获取而非零。保留原角色边界，不擅自授予财务权限。
3. 老板视图所有金额图表及排名同步所选周期；移除随机增长，不补造增长数据。客户数保留预约顾客口径并改清晰文案，只统计该周期内非取消预约，不把其误称已消费顾客。仍仅同店，不改成跨店权限。员工数量使用员工表。
4. 发型师保留本人/本店既有访问规则；月服务次数、类型和月金额使用相同时间口径，管理汇总标注仅当前在职设计师归属项目产值，不冒称全店实收。不调整项目分配或提成比例。
5. 每页说明口径、待核对历史记录、数据截止时间，支持刷新并防止过期请求覆盖；补合成HTTP与逻辑测试、构建、后端启动及浏览器Network验收。

## 需业主决策（跳过不阻塞本批）

- 旧代码`月业绩×15%`预计提成无门店配置来源。本批保留原比例，明确标为历史算法参考，不作为确认的工资规则。门店确认比例、计提基数及退款处理后单独整改。
- 项目金额与结算总额可能因整单优惠不同；本批保留既有项目金额归属，不擅自重新分摊优惠、改提成基数。
