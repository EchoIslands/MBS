# 非微信收款时间维护计划（2026-10-23）

## 目标与业务边界
在现金、银行卡等店员现场收款流程中，允许经办人记录付款发生时间，并独立保存服务器录入时间与经办员工 ID。两者分别呈现，财务和结算列表按实际业务时间排序。余额扣款沿用数据库实际扣款时间；微信继续使用微信支付成功时间；不变更支付宝支持状态、定价/折扣、退款、资金核销规则或历史时间。

## 调查证据
- 现有数据库安装器按迁移号顺序执行 025–039，发布验收器只检查字段/触发器/RPC 权限，不检查收款时间字段类型或不可变规则。
- 已完成财务统计优先采用可信微信成功时间，其他结算回退到结算创建登记时间；现金/卡没有单独可追溯的录入者时间。
- 开单结算可通过数据库原子 RPC 完成扣款与结算；需确认其 INSERT/UPDATE 与后续确认收款路径均记录同一组字段，防止仅前端改展示。
- 私有使用手册不得纳入仓库、网站或部署产物。

## 实施步骤
1. 只读核对目标 Supabase 项目 `public.settlements` 新增字段、相关触发器/RPC 的真实结构；只打印元数据，不读取客户详情或密钥。
2. 将迁移 039 的字段、数据库约束/触发器与原子结算 RPC 更新为审慎、幂等实现；不回填历史记录。补充安全安装/升级命令及只读 release 验收。
3. 收银端只对现金/银行卡提供北京时间手选；提交时走原子 RPC。余额时间由数据库生成；微信仍用可信渠道回执。保留实际业务时间、服务器登记时间和登记员工 ID。
4. 结算明细、排序、搜索、财务页及导出显示明确来源和双时间；旧记录明确标注“无付款发生时间记录”，不冒充创建时间。
5. 增补数据库隔离、RPC/HTTP、财务口径、浏览器交互和回归测试；本地构建与健康检查通过后更新状态日志。

## 验收标准
- 手选现金/卡时间精确到分钟，明确按北京时间解释；无值时由服务端完成时记录，不可未来超过 5 分钟。
- 支付状态转为已完成的同一数据库事务内记录发生时间、服务器录入时间、员工 ID；完成后不可改写；余额不接受手选时间。
- 微信时间来源和支付宝原有行为不变，旧单不回填；搜索与新旧排序口径一致。
- 本地全量测试/构建/页面验收通过；不提交、不推送、不连接数据库写入、不操作真实交易。

## 待核实事项
迁移实施前核对实际生产元数据；若发现字段或触发器已存在但不兼容，停止自动改写并报告。生产迁移另由业主按本地变更/手工发布流程执行。
