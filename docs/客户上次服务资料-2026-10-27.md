# 客户基本资料补齐上次服务

## 需求与范围

- 新增、编辑客户的基本资料直接显示上次服务发型师、上次服务时间（北京时间）、上次消费项目，允许门店手工录入、修改和清除。
- 复用 customers.last_stylist、last_visit_at、last_service_items，不另建客户副本；卡片、表格、导出和原有客户接口共用档案。
- 预约创建、改期、取消和仅标记服务完成不提前登记消费。正式结算完成时，在原数据库事务内从实际到店记录同步发型师、时间和服务项目；余额、现金、微信、次卡抵扣走同一入口。
- 新触发器只处理新完成的、有服务明细的结算，不重放旧单、不回填历史、不改变金额及奖励规则。数据库迁移由项目主人执行。
- 人工修改保留原有差异提交、旧值并发校验，避免过期编辑覆盖刚完成的结算资料。

## 验收

1. 基本资料区无需展开即可录入三项；新增后重新读取、两视图切换和编辑均保留；不修改不发送字段。
2. 未结算预约不改变三项，正式结算自动保存预约发型师及实际服务项目；重复完成不覆盖之后的人工修正。
3. 无预约直接开单也记录实际服务员工；商品单、无服务明细单不清空原服务资料；跨店记录不串写。
4. 同事务失败一起回滚；受限角色不能直接调用触发函数。
5. 隔离数据库测试、真实 HTTP 合成数据测试、生产构建、后端启动及浏览器 Network 验证。生产数据不做写入测试，不代提交或推送。

## 发布

- 先执行 setup-db 安装 044，再 verify-release 核验，然后发布网页/API。此次客户档案变化无需另行上传小程序。
- 线上门店实际预约结算及新增客户验收由主人发布后操作；本地通过不替代线上验收。

## 实施与验证结果

- 已只读查询线上 information_schema.columns：客户三项字段及结算、到店记录的关联列类型均符合预期；未读取客户明细或写入生产。
- 已将三项从折叠的历史纠错区移到共享编辑器基本资料，两个视图共用；手工清空发型师不会再回显旧到店记录的姓名。
- 044 在结算完成状态转换后读取同客户、同店、同原结算生成的到店记录，同事务写三项。服务时间复用既有 last_visit_at，使用到店记录时间，不把支付创建/微信成功时间或未来预约时刻冒充服务时间。未结算预约继续保留原档案。
- 已覆盖手工新增、差异修改及清除；时间保持北京时间；过期旧值/缺旧值/越店修改拒绝；数组旧值比较；预约草稿、现金、余额、微信、零元次卡、重复完成、迁移重装、缺可信记录、事务回滚及函数授权。
- 生产构建成功；合成配置启动实际后端并通过 /api/health。浏览器加载生产构建，真实本地 HTTP 新增、GET重读、表格切换、编辑、刷新、无修改保存均通过，无页面异常或API失败；390px窄屏三项可完整显示。
- 尚未安装生产044、发布网页/API或执行真实顾客业务。原有小程序私有配置和此前未提交修改均保留。

## 主人发布操作

在 PowerShell 项目根目录执行：

```powershell
Set-Location 'E:\01Programe\01MBS\MBS'
npx tsx scripts/setup-db.ts
if ($LASTEXITCODE -ne 0) { throw '数据库更新失败，停止发布' }
npx tsx scripts/verify-release.ts --expected-pending-passwords 18
if ($LASTEXITCODE -ne 0) { throw '发布检查失败，停止发布' }
```

18为主人上次确认的待首次设密数量；门店仍在新增客户，若数量变化，先核对本次新增来源和实际数量，再填写参数，不初始化密码来消除提示。

成功标志：setup-db显示025–044已全部提交，verify-release显示passed:true，检查函数41个。之后由主人提交、推送本批代码；Vercel Ready后，网页“客户管理→添加客户”基本资料直接显示三项。用门店实际业务验证下一次预约正式结算后的档案更新，不使用真实顾客资料做虚假结算。
