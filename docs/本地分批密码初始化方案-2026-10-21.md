## 本地运行

在 PowerShell 进入项目根目录：

```powershell
Set-Location 'E:\01Programe\01MBS\MBS'
npx tsx scripts/init-legacy-passwords.ts --dry-run
```

脚本自动读取该项目根目录 `.env` 的 `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`，环境中已设置的同名变量优先；不需要把密钥写在命令中或发给任何人。依赖均已在项目中，无新增安装包。

只读检查成功显示“结构检查通过，待初始化 N 条；未生成哈希、未写入数据”。确认连接的是计划操作的项目，且强制改密版本已准备完成后，执行：

```powershell
npx tsx scripts/init-legacy-passwords.ts
```

每批先显示读取条数和哈希生成状态，再显示写入状态，最后显示累计成功/跳过数量。末批不足 50 条照常处理。“已无 NULL/空字符串密码”表示完成。日志不含手机号、客户 ID、密码哈希或密钥。

本脚本使用项目已有 `bcryptjs` 实现 bcrypt，cost12，每条随机盐。请求经 Supabase REST API，不经过网页 SQL Editor，也不在数据库里做耗时哈希；每个请求设置 30 秒超时。空值范围是 NULL 与精确空字符串，不处理纯空格或其他非空内容。

每批 50 条是处理分组，写入采用最多 4 个并发的逐条条件 UPDATE，不是一个 50 条全成全败的事务。这样每条不同哈希与“写入时密码仍为空”的条件可以一起落库，避免无条件 upsert 覆盖已有密码。强制改密、密码与未核实身份状态在同一条 UPDATE 中保存。

若按 Ctrl+C，等待当前哈希和在途更新结束后退出，已成功记录保留；再次执行同一命令继续。网络/权限/字段错误时非零退出，同样可修复后重跑；不输出“完成”冒充整批成功。最终数量仅统计本次运行；并行运行或客户自行设密会记为跳过。与旧一次性 SQL 不同，每次运行都会继续处理当时仍为空的记录，包括后来新增记录。

字段缺失时脚本在写入前拒绝执行；按既有 025–029 迁移流程补齐并核对结构即可，不需要再运行网页上那个耗时初始化 SQL。脚本不会自动执行 SQL、修改结构或删除旧运行账本。此前网页超时是否已经提交不需要猜测：现有非空哈希会被跳过。
