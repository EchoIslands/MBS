# 微信收款核对反馈修复计划（2026-10-24）

## 问题与范围

结算管理详情的“核对微信收款与支付时间”成功后只刷新数据，没有持续的成功提示；已保存可信微信凭据的完成单还会直接返回本地数据，使主动核对看起来没有反应。

仅调整结算管理反馈、主动核对请求与对应后端分支及隔离测试。不改变金额、定价、权限、收款时间来源或数据库结构，不执行生产收款/关单，不代提交或推送。

## 实施与验收

1. 主动点击显式请求微信查单；普通幂等确认仍可读取已保存凭据。查询必须沿用原商户单，成功后仍走现有原子登记。
2. 详情内明确显示核对中、成功（金额、微信成功时间）或错误，保留搜索和详情上下文；异步返回不能打开已关闭的详情或替换另一张订单。
3. HTTP 回归覆盖已完成单主动查单、重复查单、金额/凭据异常、权限及查询失败；异常不能抹除已登记收款。
4. 本地构建、实际后端启动、隔离浏览器 Network 验证通过后更新日志，提供手动推送命令。真实微信查询由用户部署后验收。

## 验证结果

- `npm run test:security`：34 项通过、0 失败；新增用例覆盖主动向原微信单查单、重复核对、权限拒绝和金额/交易号/时间不匹配与微信查询失败，保证原凭据不会被覆盖。
- `npm run build`：TypeScript 与 Vite 生产构建通过。
- 本地 API 服务启动成功，`/api/health` 返回 `200`。隔离 HTTP 验收对合成的 33.64 元订单发送强制核对请求，返回原金额、可信北京时间 `2026-10-24 15:34:31`、原微信交易号和 completed 状态；没有请求创建支付。
- 合成页面前端已以真实 API 模式启动。DevTools 截图中的 Supabase Storage `ERR_CONNECTION_RESET` 是头像/图片资源加载错误，与本次收款核对 POST 无关；它不会解释按钮无反馈。
- 已执行 `git diff --check`，通过（仅有 Windows CRLF 提示）。本地未连生产数据库、未执行真实微信查单/付款、未修改客户或账务数据。

## 发布后验收

在结算管理打开微信已完成的结算详情，点击“核对微信收款与支付时间”。按钮应短暂显示“向微信核对中...”，随后显示实收金额及微信返回的北京时间；如果微信侧订单信息与已保存凭据不一致，会显示明确错误并保留原记录。核对只查询原商户单，不会再次发起扣款。合成 HTTP 已验收，线上真实订单查单需要部署后验证。
