# Vercel 单入口部署修复

截图确认提交 0c50ec0 的部署因 Hobby 最多 12 个 Serverless Functions 而失败。当前 api 目录包含 18 个 TypeScript 文件；functions 配置及 rewrites 不会把其余文件自动排除，工具模块也会被扫描为部署入口。

整改：仅保留 api/index.ts，其他文件按原相对层级移至 backend，统一修正入口、开发命令、类型检查及测试引用。既有 server 目录保持原用途；API URL、权限及资金业务规则不变。移除已被忽略的 memory 配置。

验收：api 下只有一个可部署文件；入口导入 backend/app.js；本地构建、隔离安全/事务回归及真实入口 HTTP 检查通过。更新宪章，说明 functions 并非入口白名单。生产部署数量、Ready 状态及 H5 登录仍须用户推送后核验。本轮不自动提交、推送或访问生产数据。

## 实施和验证结果

- api/index.ts 保留 URL 和处理逻辑，动态导入改为 ../backend/app.js。其余 18 个文件（17 个 TS、1 个 SQL）搬至 backend，逐文件与 HEAD 比对，规范化换行后内容完全一致；不删除业务模块、不移除安全校验。
- 同步 package.json、nodemon.json、tsconfig.json、README 和测试引用。vercel.json 保留单入口及原 maxDuration，includeFiles 改为 backend/shared/server，并移除当前计费模式不支持的 memory。
- 安全回归从直接 app.listen 改为通过 api/index.ts 的真实 handler 接收 HTTP 请求，以验证动态导入、鉴权和密码接口链。新增目录检查，防止业务模块再次误放 api。
- npx tsx --test tests/*.test.ts：38/38 通过；npm run build：通过（既有大包体警告）；npm run server:api：合成配置启动，GET /api/health 返回 200、success:true；git diff --check 通过。本轮未做浏览器/微信客户端验收，未执行 Vercel 云端构建或部署，线上函数数与最终 Ready 待用户推送验证。
- 全部测试使用本地合成配置和隔离数据库，不读写生产；未暂存、提交或 push。用户已明确今后由其手动执行 Git 命令。
