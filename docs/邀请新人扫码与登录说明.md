# 邀请新人扫码与登录说明

核对日期：2026-11-14。本次修正位于发布准备分支；是否上线以 `current-state.md` 的发布记录为准。

## 为什么之前进了网页

原 `POST /api/referrals/invite` 将 `https://www.hsxx8888.cn/invite?ref=...` 交给普通二维码库生成图片。这种二维码只包含网页地址，不是微信小程序码。分享给好友的“小程序卡片”本来就可以打开小程序，但保存二维码、打印二维码的入口走了另一条路径。

本次改为调用微信 `wxacode.getUnlimited`，页面固定为 `pages/invite/claim`，邀请码放在 `scene` 中。默认打开正式版；生成失败直接说明原因，不再用网页二维码替代。邀请码记录仅在生成成功后保存。H5邀请页也展示同一张小程序码；复制链接明确标记为“备用网页版链接”。

## 新人的操作

1. 微信扫一扫新生成的小程序码，进入小程序邀请领取页。
2. 点击领取，未登录时进入验证码登录；新顾客无需先到店建档。
3. 登录成功保留邀请码并回到领取页，点击领取。后台只给当前已验证的本人账号发券，不按任意输入手机号代领。
4. 朋友圈邀请入口也转到领取页；小程序码在本地写成图片文件后显示、预览和保存，避免真机不支持直接显示 Data URL。

旧的网页二维码及已经打印、发送的图片不会自动变化，需要从邀请页重新生成、保存和分享。备用网页领取入口改为优先验证码登录，并在登录后返回原邀请码；领取成功不再自行改写本地顾客身份。

## 发布与配置

- 后端须部署包含本次修改的代码，H5验证码入口也须随前端构建部署。Git分支存在不等于正式网址已经更新。
- 后端使用 `WECHAT_MINI_APP_ID`（缺省兼容 `WECHAT_APP_ID`）和 `WECHAT_MINI_APP_SECRET`，与小程序身份校验复用。密钥只留在服务端。
- `WECHAT_INVITE_ENV_VERSION` 默认 `release`。正式推广使用正式版；`trial` 仅供已经添加体验权限的人测试，不能给普通新客绕过体验权限。
- 微信要求目标页实际可用；若提示页面尚未发布，须先发布包含邀请领取页的正式小程序。代码审核通过和点击发布是不同步骤。
- 小程序领取页、真机图片显示、朋友圈入口等客户端修正须随下一包上传、体验验证及发布；更新后重新生成邀请图片。

## 已有证据与仍需核对

本地合成测试覆盖原生码请求参数、微信错误响应不会伪装成图片、scene解码、登录返回邀请码、朋友圈入口及既有分享封面。本轮测试没有向微信申请真实小程序码，也没有调用生产发券。上线后须用未登录的新手机实际扫码，确认打开的是本小程序、能收验证码、能登录并且券与推荐关系归属正确。

微信接口参考：[获取不限制的小程序码](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/qrcode-link/qr-code/getUnlimitedQRCode.html)。
